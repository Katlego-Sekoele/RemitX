# RemitX Deployment Design — Vercel Stack

**Date:** 2026-08-17  
**Status:** Superseded by [2026-08-18-azure-neon-deployment-design.md](./2026-08-18-azure-neon-deployment-design.md)

## Context

Azure for Students blocked Entra app registration and region policies, making CI/CD and Terraform impractical. Azure resources have been destroyed. This spec replaces [2026-08-16-deployment-design.md](./2026-08-16-deployment-design.md) for **cloud deployment**.

## Target stack

| Layer | Service | Role |
|---|---|---|
| Frontend | **Vercel** | React Router v7 SSR (`frontend/`) |
| API | **Vercel** | Flask JSON API (`api/`) — Python serverless |
| Database | **Neon** | Serverless Postgres (QA + prod branches) |
| Queue | **Upstash Redis** | Celery broker + result backend (all environments) |
| Worker | **Vercel + Celery** | Cron-triggered Celery burst (`worker/`) locally long-running Docker worker |
| Auth | **Clerk** | Dashboard-managed apps (no Terraform) |

Local development unchanged: Docker Compose with Postgres + Redis + Celery worker.

## Architecture

```
Browser → Vercel (frontend SSR)
       → Vercel (Flask API) ──enqueue──► Upstash Redis
                                              │
                                              ▼
                         Vercel Cron → Celery worker burst (worker/)
                                              │
                                              ▼
                                         Neon Postgres
```

Settlement is **async via Celery + Redis** everywhere. Cloud workers cannot run 24/7 on Vercel; **`worker/`** projects use Vercel Cron to invoke `/internal/worker/tick`, which runs a short-lived Celery solo worker against the same Redis broker.

### Vercel project model

**Six Vercel projects** from one Git repo:

| Vercel project | Root directory | Production branch |
|---|---|---|
| `remitx-api-qa` | `api` | `qa` |
| `remitx-api` | `api` | `main` |
| `remitx-web-qa` | `frontend` | `qa` |
| `remitx-web` | `frontend` | `main` |
| `remitx-worker-qa` | `worker` | `qa` |
| `remitx-worker` | `worker` | `main` |

Worker projects share `DATABASE_URL`, `REDIS_URL`, `XRPL_ENCRYPTION_KEY`, and `CRON_SECRET` (auto-generated by provision script).

### Cloud Celery worker

- **Cron schedule:** hourly (`0 * * * *` in `worker/vercel.json`) — requires Vercel Pro for that frequency; Hobby is once per day
- **Endpoint:** `GET /internal/worker/tick` (Bearer `CRON_SECRET`)
- **Runtime:** up to 60s Celery solo worker burst (`remitx_worker/runner.py`)

Local Compose still runs `celery worker` continuously via `Dockerfile.worker`.

### Vercel IaC & CI/CD

- **`vercel/projects.json`** — six-project layout
- **`scripts/cloud/provision.sh`** / **`destroy.sh`**
- **`.github/workflows/`** — CI + deploy all six projects on `qa` / `main`

See [vercel/README.md](../../vercel/README.md) and [scripts/cloud/README.md](../../scripts/cloud/README.md).

## Secrets

Required per cloud API project: `DATABASE_URL`, `REDIS_URL`, `CLERK_*`, `XRPL_ENCRYPTION_KEY`.

Required per cloud worker project: `DATABASE_URL`, `REDIS_URL`, `XRPL_ENCRYPTION_KEY`, `CRON_SECRET`.

Required per cloud frontend: `VITE_API_URL`, `VITE_CLERK_PUBLISHABLE_KEY`.

## Out of scope

- Azure Terraform / Container Apps
- External worker hosts (Render/Fly/Railway) — replaced by Vercel worker projects
- Clerk IaC

## Queue usage in code

Enqueue from controllers with Celery when the remittance feature is implemented. Cloud and local share the same Redis broker and task modules under `remitx_worker/`.
