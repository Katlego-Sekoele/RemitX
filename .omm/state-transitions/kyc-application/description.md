`kyc_applications.status` driven by `LEGAL_TRANSITIONS` in api/remitx_api/models/orm/kyc_lifecycle.py and `KycController.transition`. Born `in_progress` (applicant edits wizard steps), applicant submits → `submitted` (risk scored), reviewer claims → `under_review`, reviewer decides `approved` | `rejected` | `more_info_required` (each appends a `kyc_decisions` row with reason code). `more_info_required` returns the same row to `in_progress`; `rejected` and `review_due` are terminal — resubmission is a new row via `start_application`. At most one open application per user (partial unique index). Verified = approved or review_due.
