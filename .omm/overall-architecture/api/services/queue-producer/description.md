api/remitx_api/services/queue_service.py. The API's own Celery producer (`Celery("remitx_api", broker=REDIS_URL)`) — it never imports the worker app. Publishes by task name: process_integration_message, settle_remittance, burn_treasury_tokens, confirm_treasury_burn (the latter two are also called from inside worker tasks). After each `send_task`, `wake_worker()` fires a single-flight background GET to `WORKER_WAKE_URL` (proxy env ignored, 5 s timeout) so a spun-down Render worker starts; failures are only logged.
